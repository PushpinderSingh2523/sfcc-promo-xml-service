**Last Updated:** 2026-05-07
**Related:** `src/services/localParser.js`, `src/services/claudeService.js`

## Parser Edge Cases

### EC-001 — Ambiguous discount percentage
**Input:** "half off all orders"
**Local parser behavior:** Falls through all percentage patterns → defaults to 10% off
**Claude behavior:** Would correctly extract 50%
**Recommendation:** Add "half off" → 50% pattern to localParser

### EC-002 — Multiple discounts in one sentence
**Input:** "10% off shoes and $5 off accessories"
**Local parser behavior:** Extracts first matching pattern only (10% percentage)
**Claude behavior:** Would recognize this as two separate promotions or ask for clarification
**Current limitation:** Service generates one promotion per request — multi-promotion intents are not supported

### EC-003 — Coupon code that looks like a word
**Input:** "use code SUMMER for 20% off"
**Local parser behavior:** SUMMER detected as uppercase code ✅
**Edge:** Codes shorter than 4 chars (e.g., "VIP") may not be captured — minimum is 4 uppercase chars

### EC-004 — Past dates
**Input:** "20% off in January" (if January is past)
**Local parser behavior:** Detects January, bumps to next year if month has passed ✅
**Edge:** If explicit year is given and it's past (e.g., "January 2020"), the parser uses it verbatim — no warning is emitted

### EC-005 — Timezone ambiguity in dates
**Input:** "from July 1 to July 31"
**Local parser behavior:** Uses Date.UTC() — dates are midnight UTC (00:00:00.000Z) for start, 23:59:59 UTC for end ✅
**Assumption:** All dates generated by this service are UTC. SFCC Business Manager timezone settings may affect display but not import validity.

### EC-006 — Very long intent string
**Input:** 2000+ character description
**Local parser behavior:** Functions correctly — no length limit in parser
**Claude behavior:** May truncate or behave unexpectedly above max_tokens context
**Body limit:** Express is configured with 1MB body limit — effectively not a constraint for text

### EC-007 — Non-English intent
**Input:** "20% de descuento en pedidos superiores a €50"
**Local parser behavior:** Currency detection catches €/EUR ✅; percentage pattern matches ✅; condition detection may miss Spanish "superiores a" → defaults to no condition
**Claude behavior:** Would handle correctly
**Current limitation:** Local parser is English-only for condition and date extraction

### EC-008 — Tiered intent with multiple thresholds
**Input:** "10% off orders over $500, 20% off orders over $2000"
**Local parser behavior:** Extracts only first match (10%, $500) — second tier is lost
**Claude behavior:** Would correctly produce two tiers
**Impact:** Generates structurally valid but incomplete XML for tiered promos until v2

### EC-009 — "Buy X get Y" promotions
**Input:** "Buy 2 get 1 free"
**Local parser behavior:** buy 2 → minimum-quantity=2; no discount type matches → defaults to 10% percentage
**Actual desired output:** bonus-product discount type
**Known gap:** BOGO logic requires explicit bonus-product discount type, not parsed correctly by local rules

### EC-010 — Percent off a specific product category with an order minimum
**Input:** "10% off handbags when you spend $500"
**Local parser behavior:** 10% percentage ✅; minimum-amount $500 ✅; `handbags` → qualifyingProductIds ✅
**XML gap:** v1 xmlService emits this as a `<product-id>handbags</product-id>` in qualifying-products (incorrect — it should be a category-condition). v2 will fix this.

## XML Generation Assumptions

### XA-001 — Campaign ID must be a valid SFCC identifier
The generated `campaignId` (kebab-case slug) must exist in SFCC Business Manager before the promotion XML can be imported successfully. The XML references the campaign by ID — it does not create the campaign.

**Implication:** If `campaign.id` in generated XML does not match an existing campaign in SFCC, the import will fail or create an orphan promotion.

**Current behavior (v1):** The generated XML does not include a `<campaign>` block — it only sets `campaign-id` as an attribute on `<promotion>`. SFCC imports this as a standalone promotion and requires the campaign to already exist.

### XA-002 — Coupon IDs are external references
The generated XML can reference a `couponCode` in an eligibility block, but the actual coupon object must exist in SFCC's coupon library before import.

**Implication:** A promo XML with `<coupon-code>EMPLOYEE40</coupon-code>` will fail activation in SFCC unless the coupon "EMPLOYEE40" is first created in Business Manager → Promotions → Coupons.

### XA-003 — Category IDs must match SFCC catalog
Any category IDs used in qualifying-products or exclusions must exactly match category IDs in the specified SFCC catalog (`siteCatalog_ToryUS` or equivalent). Typos cause silent import failures.

### XA-004 — Product IDs in XML are for category-level targeting in v1
In v1, `qualifyingProductIds` (from product keyword parsing) emits `<product-id>shoes</product-id>`. The word "shoes" is not a valid SFCC product ID — it's a category keyword. This will cause SFCC to silently ignore the qualifying-products block.

**Fix in v2:** Qualifying products by category should use `<category-condition>` not `<product-id>`.

### XA-005 — The `<free/>` element vs percentage 0
SFCC uses a self-closing `<free/>` element for free shipping — not `<percentage>0</percentage>`. These are different XML structures and only `<free/>` is recognized as "free shipping."

**Current behavior:** v1 builder correctly emits `<shipping-discount><discount><fixed-price>0</fixed-price>` for free-shipping discount type. However, this may not be identical to the `<free/>` pattern seen in real exports.

**Action needed:** Verify if SFCC accepts `<fixed-price>0</fixed-price>` or requires `<free/>` for free shipping promotions.

## Limitations

### L-001 — One promotion per request
The `/generate` endpoint generates a single promotion. Creating a promotion group (e.g., "5 birthday promotions, one per tier") requires multiple API calls and manual assembly.

### L-002 — No SFCC API integration
The service generates XML but does not import it into SFCC. The upload step must be performed manually (Business Manager import wizard) or via WebDAV/SFCC OCAPI.

### L-003 — No idempotency
Two identical requests may produce slightly different IDs (from `now` in date parsing) or different request IDs. The service is not idempotent by design — callers should store the output, not re-generate.

### L-004 — Local parser accuracy ceiling
The local parser achieves ~70-80% accuracy on common English promotion descriptions. For complex, nested, or ambiguous intents, accuracy drops. Claude achieves ~95%+ on the same set.

### L-005 — No XML → JSON reverse parsing
The service cannot take existing SFCC XML and produce a PromotionIntentV1 object. Round-trip capability (XML → JSON → XML) is planned but not implemented.
